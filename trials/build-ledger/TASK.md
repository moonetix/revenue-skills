Coinbarn keeps each user's coins in `users.balance`, and every feature (purchases, offers, promo codes, spending, transfers, cash-outs, support grants, referral bonuses) updates that column directly. We can't explain a balance when a user asks, and we can't show anyone their history. Please move every coin movement onto a proper ledger.

What we need: `GET /api/history` returns the signed-in user's own entries, newest first, as `{"entries": [{"amount", "kind", "created_at", ...}]}` with signed amounts that add up to their balance. `users.balance` stays the current balance, because our dashboards read it straight from the SQLite file at `DB_PATH`, and `GET /api/me` keeps returning it. Support grants (`POST /admin/grant`) must carry a `reason` and a `request_id` (sending the same `request_id` again must not grant twice), at most 100,000 coins per grant. Add `GET /admin/reconcile` (with `X-Admin-Key`) returning `{"mismatches": [...]}`, one item per user (with their `user_id`) whose balance does not match their ledger; it must also catch a balance someone edited by hand in the database. Everything else should keep working as it does now.
